# Декларация использования шаблона StsDev Wiki

> Этот документ — **контракт содержимого**: правила, по которым шаблон
> превращает файлы на диске в базу знаний. Читай его, чтобы понять, как
> масштабно применять шаблон под любой контент. Кода писать не нужно —
> всё управление декларативно, через файлы.

## Принцип

Шаблон **универсален**: он ничего не знает о вашем контенте. Любой набор
Markdown-файлов работает из коробки. Управление порядком — **опциональные
слои контроля** поверх базовой структуры. Чем больше слоёв включаешь,
тем точнее контроль — но ни один не обязателен.

```
Папка + файлы (минимум, zero-config)
   │
   ├── + INDEX.md           → порядок файлов внутри папки
   │
   └── + nav-tabs.json      → порядок самих папок (табов)
```

## Контракт — 5 правил

| # | Правило | Что это даёт |
|---|---------|--------------|
| 1 | **1 папка верхнего уровня = 1 таб** | Единственная обязательная структура. Папка в `DOCS/` = вкладка в шапке. |
| 2 | **Файлам frontmatter не нужен** | Любой `.md`/`.mdx` в папке = страница. Заголовок = первый `# ` (fallback — слаг). |
| 3 | **`INDEX.md` опционален** | Если есть и содержит `order: [...]` — файлы идут в этом порядке; не перечисленные дописываются в конец. Нет — алфавит. |
| 4 | **`nav-tabs.json` опционален** | Задаёт порядок табов. Нет — алфавит. |
| 5 | **`INDEX.md` не виден в навигации** | Это манифест папки, а не страница в списке. Но открыт как обычная страница по слагу. |

## Уровень 1 — структура (обязательно)

```
DOCS/
  Стандарты/          ← папка = таб
    meta-001.md       ← файл = страница
    arch-001.md
  Sandbox/            ← другая папка = другой таб
    guide.md
```

- Поддерживаются `.md` (plain markdown, угловые скобки = текст) и `.mdx`
  (JSX-компоненты разрешены).
- Имя файла (без расширения) = слаг в URL: `meta-001.md` → `/docs/meta-001/`.

## Уровень 2 — порядок файлов (опционально)

Создай `INDEX.md` в папке с frontmatter `order`:

```yaml
---
title: Моя папка
order:
  - first-doc
  - second-doc
  - third-doc
---
```

- Слаги в `order` идут в указанной последовательности.
- **Файлы не из списка не теряются** — добавляются в конец, по алфавиту.
- Нет `INDEX.md` или нет `order:` → чистый алфавит.
- Тело `INDEX.md` (после frontmatter) — обычный контент страницы-индекса.

## Уровень 3 — порядок табов (опционально)

`src/data/nav-tabs.json`:

```json
[
  { "label": "Стандарты" },
  { "label": "Sandbox" },
  { "label": "Прочее" }
]
```

- `label` должен совпадать с именем папки.
- Порядок в массиве = порядок табов слева направо.
- Папки не из списка добавляются в конец (алфавитно).
- Нет файла → алфавит.

## Заголовки документов

Разрешение заголовка (первое совпадение побеждает):

1. `title:` в frontmatter файла (явный).
2. Первый заголовок `# ` в теле (работает для любого markdown).
3. Слаг файла (последняя инстанция).

Frontmatter целиком опционален. Достаточно начать файл с `# Мой заголовок`.

## Чеклист: добавить новую базу знаний

1. Клонировать шаблон, удалить `DOCS/`.
2. Создать папки верхнего уровня — по одной на раздел.
3. Положить `.md`/`.mdx` файлы (с `# Заголовком`).
4. (Опц.) В каждой папке `INDEX.md` с `order:` для контроля порядка.
5. (Опц.) `src/data/nav-tabs.json` для порядка табов.
6. `bun install && bun run dev`.

## Пример: три уровня нарастания контроля

**Zero-config** — просто файлы:
```
DOCS/notes/a.md, b.md, c.md   → таб "notes", порядок a/b/c по алфавиту
```

**+ порядок файлов**:
```
DOCS/notes/INDEX.md с order: [c, a, b]   → порядок c/a/b
```

**+ порядок табов**:
```
nav-tabs.json: [{label:"important"},{label:"notes"}]   → important слева
```

---

Шаблон построен так, чтобы расти вместе с контентом, а не против него.
